# DFlash Just Made AI 6x Faster : DFlash, DeepSpec Explained

Six times the throughput, zero quality loss. That is the claim behind D flash, freshly merged into llama.cpp for the Qwen 3.6 family. And the moment you hear faster with no downside, the honest reaction is suspicion, because that trade almost never exists. Faster usually means dumber, or quantized, or cut down somewhere you do not notice until it matters. So, the real question is not whether it is fast. Anyone can post a speed number. The question is whether the word lossless has contact with an actual benchmark. Because if it does, this changes how local models run. If it does not, it is just another chart. Here's what actually shipped. D flash is a speculative decoding method, now merged straight into llama.cpp, aimed at the Qwen 3.6 family. On the Qwen 3 8 billion build, plain auto-regressive decoding runs at 38 tokens per second. Block diffusion pushes that to 97. Eagle 3, the previous lossless champion, hits 114. D flash clears 400. That is the headline. Here's what it skips, how it gets there, and whether the output is still the same model underneath. So, three things. First, how D flash actually pulls this off. Second, deploying it on your own machine in basically one click with llama.cpp and Docker. And because claims are cheap, third, we benchmark it ourselves to see if lossless is real. Start with why decoding is slow in the first place, because that is the whole reason any of this exists. A classic language model generates one token per forward pass. One at a time, in order, each token waiting on the one before it. And on a GPU sitting in someone's home, the bottleneck is not compute. It is waiting. Verifying 16 tokens in a single pass costs almost the same wall clock time as generating one. You're paying for memory bandwidth, not math. The chip mostly sits idle, waiting for data to load. That idle time is the opening. If you could push a whole batch of tokens through in one pass instead of one at a time, you would actually use the hardware you already paid for. That is the entire idea behind speculative decoding. Speculative decoding works like this. A small, fast drafter guesses a block of tokens. Then the big, accurate model verifies the whole block in one pass. Every token it agrees with, you keep for free. The first token it rejects, you throw away everything after it and let the big model correct that one. The math is simple. Per token latency is drafting time plus verification time divided by tau, the average number of tokens accepted per cycle. Two levers. Make drafting cheaper or make drafts better so more get accepted. Every method is a different bet on those two. And here's where the previous methods hit a wall. Eagle drafts auto regressively one token at a time the same way as the model it is trying to speed up. So the drafting cost grows with every token you speculate. To keep it cheap, the drafter has to stay tiny. Basically a single transformer layer. And a one layer model is a weak language model. It lands around three accepted tokens per cycle and pushing the budget higher barely helps. Acceptance flattens while cost keeps climbing. One wrong token kills everything behind it. That is the ceiling. To break it, you need a drafter whose cost does not scale with the number of tokens it drafts. That is exactly what a diffusion model gives you. Instead of writing left to right, a diffusion drafter starts with a block of mask slots and fills them all at once in a single pass. Same number of steps, far more tokens. In one comparison, the diffusion drafter produced 108 tokens where the auto regressive one produced 21. But there is a subtler trick and it is the actual innovation. How does a drafter know what to guess? As the big model reads your prompt, its inner layers already form a strong hunch about the next few words. The question is where you hand that hunch to the drafter. Eagle hands it over once at the very beginning. So, the signal fades as it passes deeper through the layers. The drafter stays shallow, and shallow means weak. Dflash pins that knowledge to every layer. The hunch does not decay, so the drafter can go deeper without going blind, and a deeper drafter guesses better. Here is the payoff. MTP, the older approach, drafts one token per forward pass. So, seven tokens means seven passes. Dflash proposes a block of 16 tokens in a single pass, because a diffusion drafter barely cares about block size. Both end up accepting almost the same number of tokens per cycle, a tau of 67 versus 73, close enough to call even. Acceptance is not the difference. Time is. MTP paid for seven sequential passes. Dflash paid for one. Same output, a fraction of the cost. That is the theory. Now, the part that matters. Does it hold up when you actually run it? Deploying it is close to one click. The context length, the model, and the drafter path. One knob worth knowing about is the drafter quantization. A less quantized drafter guesses more accurately, but costs a little more. A smaller one runs faster with weaker drafts. Speed depends on context, and this is the surprising part. Most models get slower and worse as context grows. D flash gets relatively faster. At a 36,000 token context, the gap hit 4.4x on tokens. The longer the job, the more it wins, which is backwards from how this usually goes. Now the honest costs. First, VRAM. The drafter is not free.
